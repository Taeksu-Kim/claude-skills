# 스킬 이력 (NOTES.md) — NOTES.md를 만들거나 기록할 때, 스킬에 "함정"·"관리" 절을 넣을 때, 검토에서 관리·추적 질문을 볼 때 읽는다

LLM은 세션이 끝나면 경험이 쌓이지 않는다. `NOTES.md`가 그 스킬의 경험이다 — 실패가 규칙으로 돌아오면서 스킬이
상식 수준에서 그 일만의 전문성으로 자란다. 공용 스킬 폴더(`side_projects/`)는 git 저장소가 아니라 이력을 파일로 남긴다.
스킬을 **쓸 때**는 `NOTES.md`를 읽지 않는다. 고치기 전에는 색인만, 검토할 때는 끝까지 읽는다.

## NOTES.md 구조 — 이 순서 (위만 읽어도 상황이 잡히게)
```markdown
# <스킬 이름> 노트

## 설계
하는 일 · 쓰는 사람 · 성공 기준 · 부르는 때 · 입력 · 결과 · 되돌리기 어려운 동작 · 실패 신호
(칸마다 근거 또는 `가정:`. 만들기의 방향 확인과 범위 기록이 여기 들어간다)

## 만든 과정
스킬 없이 돌렸을 때 틀린 곳: <한두 줄, 또는 "돌려 보지 않음">
| SKILL.md 규칙 (절) | 출처 | 결과를 바꾸는 사례 |
|---|---|---|
| 비유는 특징 대조로 고른다 (쓰기) | 사용자 수정 F2 / 저장소 실례 | 친숙한 비유가 자동성을 덧붙인 초안 |
| 뺀 것 | 이유 |
| "명확하고 간결하게" | 상식 — 지워도 똑같이 함 |
(규칙이 바뀌면 이 표도 같이 고친다)

## 색인 (현재 유효)
- [D1] 2026-11-18 · 결정 · 사람에게는 방향만 묻는다
- [F1] 2026-11-20 · 실패 · 짐작으로 형식 확정 → 덧대기 · 해결 (만들기 1단계)

## 항목
(색인 번호 순. 아래 형식)

## 변경
- 2026-11-20 · 만들기 1단계에 "형식은 `가정:`" 추가 · → F1

## 지난 것
(해결·대체된 항목의 색인 줄. 자세한 내용은 한두 줄로 줄인다)
```

## 항목 형식 — 칸을 고정한다 (같은 칸끼리 비교되게)
- **[F] 실패**: 입력 · 증상 · 원인 · 조치(바꾼 규칙 위치) · 상태(해결 / 감시 / 미해결)
- **[D] 결정**: 결정 · 이유(출처) · 버린 대안과 그 이유 · 다시 볼 조건
- **[C] 주의**: 알려진 한계 · 언제 걸리나 · 우회법

"버린 대안"이 있어야 같은 대안을 다시 검토하지 않고, "다시 볼 조건"이 있어야 조건이 바뀌었을 때 옛 결정에 묶이지 않는다.

## 기록 기준
- 기록한다: 규칙을 바꾼 실패 / 한계를 드러낸 실패 / 대안을 버린 결정 / 사용자가 결과를 고친 것 중 같은 모양이 다시 나올 만한 것
- 기록하지 않는다: 오타·문구 수정, 한 번뿐인 환경 문제, 이미 있는 항목과 같은 것 (그 항목의 상태만 갱신)
- 비밀값·개인정보·회사 정보는 쓰지 않는다

## 고리
- **규칙 ↔ 번호**: `SKILL.md` 규칙 끝에 `(F3)`, 항목의 "조치"에 규칙 위치. 평소엔 몇 글자, 이유가 궁금할 때 그 번호만 찾아 읽는다.
- **함정 줄**: [F]를 쓰면 **바로** 그 스킬 `SKILL.md`의 "함정" 절에 한 줄 (번호 붙여) — `NOTES.md`는 쓸 때 읽히지 않으니
  교훈이 다음 사용에 닿으려면 본문에 있어야 한다. 함정 절이 실제 교정을 담는 가장 값진 곳이다.
- **가설 올리기**: 스킬에 `가설:` 표시로 넣은 규칙은 [D]의 "다시 볼 조건"(성과·실패 신호)으로 판정한다 — 확인되면 표시를 떼고,
  반대면 빼고 [F]로 남긴다.
- **스킬 없이 돌린 실패도 [F]**: 만들기 2에서 스킬 없이 틀린 곳은 [F]로 남기고 상태를 "해결(검증 전)"으로 — 검증에서 확인되면 "해결".
- **올리기**: 같은 모양의 [F]가 두 번 → 일반 규칙으로 올리고 함정 줄은 지운다. [D]의 "다시 볼 조건"이 오면 그 결정을 다시 연다.
- **정리**: 해결·대체된 항목은 "지난 것"으로 내린다. 색인(현재)이 30줄을 넘으면 정리하고, 파일이 200줄을 넘으면
  그때 `notes/` 폴더로 나눈다 (미리 나누지 않는다).

## 각 스킬의 SKILL.md에 넣을 절
```markdown
## 함정 (대원칙·핵심 규칙 바로 뒤 — 겪을 때마다 한 줄)
- <실제로 틀린 모양> → <대신 할 것> (F1)

## 관리 (끝)
실패 신호: <이 스킬에서 실패가 무엇인지 1~3개 — 예: 사용자가 결과를 크게 고침 / 검증 실패 / 다시 작업>.
걸리면 `NOTES.md`에 [F] 한 줄 (형식: guides/history.md).
이 스킬을 고치기 전에 `NOTES.md` 색인을 먼저 읽는다.
```
실패 신호를 미리 정해 두면 사람이 "기록해"라고 하지 않아도 기록이 남는다. 작은 스킬은 이 절과 빈 `NOTES.md`면 충분하다.
