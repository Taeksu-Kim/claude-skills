# ui-design 노트

## 설계
- 하는 일: 화면 작업을 작업 종류(새 화면·평가·다듬기·점검·작은 수정)와 화면 종류(도구·읽기·소개·작품)로 나눠
  필요한 지침만 읽게 하고, 실제 브라우저 확인으로 끝내게 한다 — `가정:` description·본문에서 복원 (2026-11-18 검토)
- 쓰는 사람: 이 스킬을 따르는 Claude Code. 결과를 받는 사람은 사용자 (방향·가치 문장·브리프·고칠 범위 확인)
- 성공 기준: `가정:` 사용자가 화면을 크게 고치지 않음 / 브라우저 확인 뒤 사용자가 새 화면 문제를 찾지 않음
- 부르는 때: description (CLAUDE.md "화면을 만들거나 고칠 때는 코드 전에 ui-design")
- 입력: 사용자 요청, 기존 화면 코드(`static/index.html`·CSS), 프로젝트 데이터·API
- 결과: 화면 코드, 브리프·비평 보고, 브라우저 확인 보고
- 되돌리기 어려운 동작: 없음 (화면 코드 수정은 프로젝트 쪽에서 되돌림)
- 실패 신호: `SKILL.md` "관리" 절

#### 주 전문가: 프로덕트 디자이너 (첫 복원에서 빠졌음 — skill-craft F3 재발, 2026-11-18 추가)
이 스킬이 대신하는 직업 자체. 인용은 모두 `[인용·미확인]`, 암묵지는 `가설:`.
- 관점: 화면 한 장이 아니라 사람이 과업을 끝내는 흐름을 설계한다. 해결안을 내 보면서 문제를 이해한다
  (문제와 해결이 같이 자람 — Lawson, Cross, Dorst & Cross 2001).
- 일하는 순서: 문제 정의 → 저충실 안 여러 개로 펼침 → 비교해 고름 → 실제 콘텐츠로 고충실 시안 → 구현·디자인 QA → 사용 관찰 → 반복
  (Double Diamond — Design Council 2005, Buxton 2007 "옳은 디자인을 고른 뒤 디자인을 옳게").
