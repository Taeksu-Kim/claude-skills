# 소개형 (Persuade) · 작품형 (Experience)

**읽는 때**: 랜딩·서비스 소개·가입 유도(소개형), 포트폴리오·갤러리·쇼케이스(작품형).
**다음**: 방향이 아직 없으면 `../topics/direction.md` → `../stages/2-build.md`.
> 이 파일은 아직 실제 프로젝트로 검증되지 않았다 (2026-11-14 기준, 사이드 프로젝트에 소개형 화면 없음).

여기서는 디자인 자체가 방문자가 평가하는 대상이다. 도구형과 달리 방향이 페이지 전체를 이끌어도 된다.

## 소개형: 먼저 설계 (코드 전)

**모을 정보** (빠진 것만 한 번에 묻는다. 답이 없으면 합리적으로 가정하고 한 줄로 밝힌 뒤 진행)
- 핵심 행동 **하나** (가입·신청·다운로드·문의), 정확히 무엇을 얻는지, 무엇을 전환으로 볼지
- 대상과 그들의 문제, **오늘 전환하지 않는 이유 세 가지**(반론), 어디서 오는지, 이미 아는 것
- 증거 (숫자, 사례, 후기, 화면·영상), 위험 줄이기 (무료 체험, 언제든 해지, 환불)

**페이지 구조**
- 첫 화면(필수): 결과+대상을 담은 제목 → 어떻게·누구를 위한지 보충하는 부제 → 주 행동 버튼(동사+얻는 것)
  → 증거 하나 → 실제 제품 화면·영상. 첫 화면에 **경쟁하는 행동 버튼 금지**.
- 중간(논증): 문제→해결 한 섹션, 이점 3~5개(결과 중심), 사용 방법 3단계, 증거(후기·사례)
- 끝(반론 처리): FAQ, 위험 줄이기, 마지막 행동 버튼(첫 화면과 동일)
- 형식 고르기: 제품이 한 장의 화면으로 이해되면 **기본형** / 의심을 풀어야 하면 **긴 이야기형** /
  이미 의도가 높은 방문자면 **최소 전환형** / "A vs B" 검색 의도면 **비교형**. 고른 이유를 말한다.

**전환 규칙**
- 유입 경로와 메시지를 맞춘다 (광고에서 오면 광고의 약속과 첫 화면을 일치).
- 기능이 아니라 이점부터. **구체적으로**: "시간 절약" ✗ → "주간 정리 4시간을 15분으로" ✓
- 반론은 각주가 아니라 섹션. 증거는 그것이 뒷받침하는 주장 바로 옆에.
- 행동은 "작동하는 형태"로: 예약이면 실제 날짜 선택이, 가입이면 실제 입력창이 첫 화면에 — 다른 곳으로 가는 장식 링크는 행동이 아니다.

**카피**: 제목 공식 "{결과}, {고통} 없이" / "{대상}을 위한 {분류}". 버튼은 동사+얻는 것("무료로 시작", "체크리스트 받기"),
"더 알아보기"·"제출" 금지. 이점 목록은 **굵은 이점** — 근거나 세부. 지어낸 후기·숫자·고객 금지.

**흔한 실패**: 첫 화면 행동 버튼 여러 개, "최적화"·"간소화" 같은 모호한 가치 제안, 결과 없는 기능 나열,
맨 아래 묻힌 증거, 모바일에서 무너지는 가독성, 다음 행동이 없음.

**만드는 순서**: 첫 화면 → 이점 → 사용 방법 → 증거 → FAQ → 마지막 행동. 섹션 단위로 (매번 전체를 다시 만들지 않는다).

## 방향이 페이지를 이끌 때의 규칙 (소개형·작품형 공통)

- 방향의 재료는 페이지를 **떠받치되 그림이 되면 안 된다**: 첫 화면 전체를 포스터처럼 칠하고 작동하는 부분이 없으면 실패.
- 어디에 놓든 부품은 작동한다: 내비게이션은 링크로 읽히고, 글은 배경 위에서 읽히고, 주 행동은 분명히 눌러볼 수 있고,
  다음 섹션은 섹션으로 시작한다.
- 방향을 강조색 하나로 축소하지 않는다 — 그건 기본 템플릿에 스티커를 붙인 것. 대신 주된 큰 수 **하나**에 집중한다.

## 작품형

작품이 첫 화면부터 주인공이고 인터페이스는 물러난다. 작품을 가리는 장식·설명 캡션·과한 UI를 줄인다.
탐색(다음 작품, 목록으로)은 늘 찾을 수 있게. 한 화면에 결정은 하나(어느 작품을 열지) — 필터·정렬·태그를 한꺼번에 노출하지 않는다.
