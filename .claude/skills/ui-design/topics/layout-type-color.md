# 배치 · 글자 · 색

**읽는 때**: 배치·간격·글자·색을 새로 잡거나, 비평에서 이 부분이 문제로 나왔을 때.
기존 방향(시각 세계)은 보존한다 — 여기는 그 안에서 구조와 사용법을 고치는 규칙이다.
화면 종류별 차이: 도구·읽기형은 예측 가능한 구조·안정된 밀도, 소개·작품형은 방향이 정당화하면 비대칭·파격 허용.

## 배치

**먼저 진단** (근거를 들어 답한다)
- **눈 찡그리기 테스트**: 세부를 흐리게 봐도 주 요소 → 보조 요소 → 큰 묶음 순서가 보이나?
- **묶음**: 관련된 것은 가깝고 다른 묶음은 떨어져 있나, 아니면 상자로 약한 근접성을 메우고 있나?
- **리듬**: 좁은 간격과 넓은 간격의 대비가 있나, 같은 값 반복으로 모든 게 같은 무게인가?
- **구조**: 반복된 카드·단이 정말 동등한 내용인가, 프레임워크 기본값인가?
- **밀도**: 사용 빈도·결정 복잡도에 맞나? / **적응**: 좁은 폭·확대에서 무엇이 재배치·접힘·줄바꿈되나? DOM·포커스 순서가 시각 순서와 같나?

**적용**
- 의미로 묶는다. 상자·장식보다 근접성 먼저. 형제 간격은 `gap`.
- 간격 체계 하나 (4 단위가 8 단위보다 중간 단계가 쓸모 있다: 4·8·12·16·24·32·48·64…). 임의 값 금지.
- 위계는 프레임워크 기본값이 아니라 제품 우선순위를 따른다. 반복은 알아보기를 돕는다 — 내용이나 우선순위가 바뀔 때만 깬다.
- 반응형은 구조로 (재배치·접기·재흐름). 같은 컴포넌트가 여러 맥락에 놓이면 컨테이너 기준.
- 깊이(그림자)는 상태나 위계를 밝힐 때만. 광학 보정은 렌더 결과를 본 뒤.
- 모서리가 중첩되면 (간격 32px 미만) **안쪽 반경 = 바깥 반경 − 간격** (결과가 2 이하면 직각).

## 글자

**진단**: 어떤 글꼴·굵기·역할이 정해져 있나, 모든 글꼴이 필요한가? 제목·본문·라벨·메타·데이터가 한눈에 구분되나?
인접한 크기·굵기가 너무 비슷하지 않나? 같은 역할이 화면마다 같은가?

**적용**
- 위계가 분명한 최소한의 역할과 글꼴. 크기만으로 위계를 만들지 말고 굵기·간격·색을 함께.
- 역할 이름(제목1·본문·라벨·캡션·숫자)으로 **한 번 정의하고 재사용**. 화면 안에 임의 크기를 흩뿌리지 않는다.
- 본문 기본 16px (밀집 역할·플랫폼 관습이 정당화할 때만 예외). iOS Safari 는 16px 미만 입력창에서 강제 확대.
- 산문 45~75자. 줄이 넓을수록 줄 간격을 더.
- 어두운 바탕의 밝은 글자는 줄 간격·자간을 조금 더, 필요하면 한 단계 굵게.
- 숫자·코드·라벨 기능 사용 (`tabular-nums` 등). 쓰는 글꼴·굵기만 로드하고 대체 글꼴 지표를 맞춘다.
- 브라우저 확대·사용자 글꼴 설정을 존중. 제목 `text-wrap: balance`, 본문 `text-wrap: pretty`.

## 색

**진단**: 확정된 브랜드색은? 현재 바탕·글자·동작·의미색 역할은? 회색 때문에 위계·상태가 안 보이는 곳은? 색으로만 전달하는 곳은?

**적용**
- 색은 견본 묶음이 아니라 **역할**로: 바탕과 띄운 면 / 주·보조 글자 / 동작·포커스·선택 / 테두리 / 성공·경고·오류·정보 / (필요하면) 데이터 범주.
- 강한 색은 흩뿌리지 말고 한 영역이나 역할을 맡긴다. 주 동작의 색을 장식에 쓰지 않는다.
- 의미색은 일관되게, 단 분야·지역 관습을 따른다 (한국 등락 색은 `korean.md`). 데이터는 색 외에 명도·모양·라벨로도 구분.
- 다크모드는 기계적 반전이 아니라 면 높이와 대비를 따로 설계.
- 새 팔레트는 가능하면 OKLCH (명도·채도를 예측 가능하게 조절). 흰색·검정 근처에서 채도를 낮춘다.
  대비가 맥락에 따라 달라지는 반투명 겹침보다 명시적 색.

**대비 기준 (WCAG AA)**: 본문 4.5:1 / 큰 글자 3:1 / 컨트롤·아이콘·포커스 3:1. 상태별·양쪽 테마·이미지 위 글자 모두 계산으로 확인.
