# 가치·밀도 자체 점검

**읽는 때**: 구현 후 스크린샷을 볼 때(`../stages/6-verify.md`), 비평을 시작할 때(`../stages/3-critique.md`).
기술 점검(콘솔·폭·클릭 대상)이 통과해도 **화면이 무엇을 위한지 안 드러나면 실패**다. 이 점검은 그걸 잡는다.

**출처**: 아래 항목 대부분은 사용자가 실제 화면(카드 게임 정보 표, 2026-11-14)을 보고 직접 내린 수정 지시를
일반화한 것이다. 화면마다 방향(밀도를 촘촘히/여유 있게 등)은 브리프에서 사용자와 정한 것을 따른다.

## 0. 기준 문장을 먼저 적는다

브리프의 **핵심 가치 한 문장**과 **주 판단·주 과업**을 다시 적는다
(예: "카드 3장 중 무엇을 고를지 바로 판단한다"). 브리프가 없으면 화면에서 추정해 적고 `(추정)` 이라고 표시한 뒤
보고에서 사용자에게 확인받는다. 아래 모든 질문은 이 문장 기준이다.

## A. 가치가 먼저 보이는가

1. **5초 테스트** — 스크린샷만 보고 이 화면이 돕는 판단을 한 문장으로 쓸 수 있나? 0의 문장과 같은가? 만든 사람은 답을 알아서 후하다 —
   새 화면·재디자인이면 `craft.md` §4-4 평가자의 ①② 답으로 판정한다.
2. 가장 먼저 눈이 가는 것이 **주 판단에 쓰는 정보**인가 (제목·장식·설명문이 아니라)?
3. 판단 결과(등급·추천·요약)가 원자료 열보다 **앞에 있거나 더 눈에 띄는가**? 첫 화면에서 가장 큰 글자의 내용을 적어 본다 —
   원값(총액)이고 판정("573,500원 넘음")은 작은 칩에 있으면 실패 (D12).
4. 화면을 이해하는 데 필요한 규칙·용어 설명이 **그것을 쓰는 곳보다 먼저 닿는 위치**에 있나 (탭 순서, 위쪽 링크)?
5. **빼기 테스트** — 요소마다 "지우면 0의 문장 전달이 약해지나?" 아니면 지우거나 접을 후보.

## B. 글이 판단을 돕는가

6. 수치를 나열하지 않고 **왜 그런지·그래서 무엇을 하면 되는지**를 짧게 말한다. 수식·원값은 뒤에 보조로.
7. 코드·데이터 구조에서 읽은 사실을 **사용 중의 의미로 번역**했나 ("중첩 +1" → "부여할 때마다 범위와 피해가 커진다").
8. 결론이 조건에 따라 달라지면 **조건형**으로 쓴다 ("인접 칸을 3개 이상 만들 수 있으면 A등급").
9. 비교 결과는 긴 문장 대신 **짧은 분류 이름**으로 (예: 레벨업 / 새 칸 / 비슷), 가능하면 그 이름으로 거를 수 있게.
10. 라벨이 무슨 뜻인지 바로 아나? 모호한 형용사 라벨("작은") 대신 정확한 명사("유닛 수").
11. 단위·표기가 사용자에게 직관적인가 (배율 1.25 → `+25%`, ×2 → `2배`).
12. 같은 말이 제목·소개문·라벨·도움말·placeholder 에서 반복되지 않나?

## C. 밀도 속에서 조작이 보이는가

13. 자주 쓰는 조작(필터 초기화, 계산기, 모드 전환)이 글·필터 무리에 **묻혀 있지 않나**? 그 조작이 바꾸는 결과
    (예: "12장 표시") **바로 옆이나 아래**에 따로 둔다.
14. 스크롤 영역은 하나. 안쪽 스크롤은 데이터가 정말 클 때만 (수백 행 이하면 페이지 스크롤로 풀기).
15. 거르기에 **포함뿐 아니라 제외**가 필요한가? 자주 보는 부분집합(예: "플레이 가능만")을 한 번에 고를 수 있나?
16. 성격이 다른 항목(사용 불가·보상 전용 등)이 섞여 있으면 **구역이나 구분선으로 나누고** 얻는/쓰는 조건을 적는다.

## C2. 에이전트 제품 화면일 때만

17. 긴 실행: 진행 상황이 보이고 취소할 수 있나? 끝나면 결과가 그 자리에서 열리나?
18. A2A 로 들어온 일이 사람이 시킨 일과 같은 목록에 보이고, 출처(사람 / 다른 에이전트)가 구분되나?
19. `reviewUrl` 로 들어오면 해당 결과가 바로 열리나 (목록부터 다시 찾게 하지 않나)?
20. 모델이 꺼져 있으면 그 기능만 잠기고 켜는 법이 보이나?
21. 고치기(직접 편집)와 다시 생성이 구분돼 있고, 다시 생성이 편집한 내용을 말없이 덮지 않나?
22. **채팅이 있는 화면만**: 세션 ①Claude Code ②로컬 LLM 선택이 있고, 대화마다 어느 쪽인지 보이고, 꺼진 쪽은 잠겨 있나?
    ①을 고를 때 내용이 외부로 나간다는 것이 보이나 (개인 데이터 앱)? 채팅이 없는 화면은 해당 없음.

## D. 밀도 수치 (판단 재료, 기준선 아님)

각 폭에서 `page.evaluate(TEXT_JS)`. 첫 화면 글자 수가 많거나 긴 문장이 많으면 B를 다시 본다.

> 외부 계약: `논문 분석 프로젝트/tools/browser_check.py`가 이 블록을 TEXT_JS 블록(이름 뒤 등호와 큰따옴표 세 개로 여는 줄)을 이름으로 찾아 잘라 읽는다. 이름·형식을 바꾸지 않는다 (D10).
```python
TEXT_JS = """() => {
  const H = innerHeight, blocks = [];
  const w = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT);
  while (w.nextNode()) { const n = w.currentNode, t = n.textContent.trim(); if (!t) continue;
    const e = n.parentElement, s = getComputedStyle(e), r = e.getBoundingClientRect();
    if (s.display === 'none' || s.visibility === 'hidden' || r.height === 0 || r.top >= H || r.bottom <= 0) continue;
    blocks.push(t); }
  const all = blocks.join(' '), digits = (all.match(/[0-9]/g) || []).length;
  return {first_screen_chars: all.replace(/\\s/g, '').length, text_blocks: blocks.length,
          long_blocks_over_60: blocks.filter(t => t.length > 60).map(t => t.slice(0, 40) + '…'),
          digit_ratio: +(digits / Math.max(1, all.length)).toFixed(2)};
}"""
```

## 보고

0의 문장, 그리고 항목마다 `OK / 고침 / 해당 없음` 중 하나. 고친 것과 사용자 판단이 필요한 것만 한 줄씩 적는다.
