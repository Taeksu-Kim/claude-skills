# 화면 문구

**읽는 때**: 버튼·라벨·에러·빈 상태·안내·확인 문구를 쓰거나 고칠 때. 모든 화면 종류 공통.

## 원칙

- 글은 장식이 아니라 디자인 재료다. 쓰기 전에 "이 화면이 무엇을 말해야 사용하기 쉬워지나"를 묻는다.
- **사용자 쪽에서** 쓴다: 시스템 구조가 아니라 사용자가 조작하고 알아보는 이름으로 ("웹훅 설정" ✗ → "알림 관리" ✓).
- 팔지 말고 무엇을 하는지 평이하게. 재치보다 구체성.
- 능동형. 컨트롤은 눌렀을 때 일어날 일을 그대로 ("변경 저장" ✓, "제출"·"확인"·"다음" ✗).
- **한 동작은 흐름 내내 같은 이름**: "게시" 버튼 → "게시됨" 알림. 같은 개념에 같은 명사·동사. 문학적 변주 금지.
  용어가 여러 화면에 흩어지면 짧은 용어집을 만든다.
- **같은 사실은 같은 표현으로** — 화면마다 숫자·명칭이 다르게 적히지 않게. 가정한 사실은 가정이라고 표시.
- 요소 하나에 역할 하나: 라벨은 라벨만, 예시는 예시만.
- 군더더기 없이 짧게. 제목이 이미 설명한 것을 소개문이 반복하면 소개문을 지운다.

## 상태별

| 상태 | 쓰는 법 |
|---|---|
| **에러** | ① 무엇이 실패했나 ② (알면) 왜 ③ 어떻게 복구하나. 사과하지 않고, 모호하지 않게. 내부 코드를 주 메시지로 쓰지 않는다. 시스템이 모르는 원인을 지어내지 않는다 |
| **빈 상태** | 처음 사용 / 검색 결과 없음 / 필터 / 권한 없음 / 실패를 구분하고, 각각 다음에 할 일을 준다. 빈 화면은 행동하라는 초대 |
| **로딩** | 실제 작업 이름 ("거래 불러오는 중…"). 오래 걸리면 솔직한 예상. 가짜 진행률 금지 |
| **성공** | 끝난 결과를 짧게. 다음에 할 일이 바뀔 때만 덧붙인다. 완료 표시는 실제 저장·전송이 끝난 뒤에만 |
| **위험한 동작** | 대상과 결과를 명시 ("거래 13건 삭제"). 안전하게 되돌릴 수 있으면 확인창보다 되돌리기. 확인창이면 버튼에도 동작 이름 ("삭제", "예" ✗) |
| **폼** | 라벨은 늘 보이게 (플레이스홀더는 예시이지 라벨이 아니다). 형식·조건은 제출 전에. 오류는 무엇을 어떻게 고칠지, 사용자 탓 없이 |
| **도움말** | 컨트롤을 반복하지 말고 암묵적 질문에 답한다. 드문 세부는 접어서 |

## 말투
- 목소리는 일정하게, 어조는 순간에 맞게. 개인정보·결제·삭제·접근 상실은 진지하게 — 친근함은 좋지만 농담은 안 된다.
- 한국어 화면: 존댓말 평서문. 제목은 명사형 또는 짧은 문장. 버튼은 "~하기" 대신 동사 원형 명사("저장", "가져오기")도 무방 — 화면 안에서 통일.
- 개수는 숫자로 ("8건"). 번역 가능하게 문장을 조각내 이어 붙이지 않는다.
