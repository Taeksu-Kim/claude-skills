# 시각 방향 정하기

**읽는 때**: 기존 디자인이 없는 새 화면에서 방향을 정해야 할 때 (소개형·작품형은 거의 항상, 도구형·읽기형은 사용자가 원할 때).
**다음**: 사용자가 방향을 고르면 `../stages/2-build.md`. 방향은 **사용자가 고른다** — 제안만 한다.

## 1. 주제에 뿌리를 둔다

브리프가 주제를 못 박지 않았으면 먼저 정하고 밝힌다: 구체적 주제 하나, 그 대상, 이 페이지의 단 하나의 역할.
구별되는 선택은 **주제 자신의 세계**(재료, 도구, 물건, 쓰는 말)에서 나온다. 실제 내용과 실제 주제로 만든다.

## 2. 후보 2~3개를 만든다 — 각각 네 가지로

- **색**: 이름 붙인 hex 4~6개 (역할: 바탕·면·글자·강조·의미색)
- **글자**: 역할별 글꼴 (도구·읽기형은 한 벌로 충분, 소개·작품형은 개성 있는 제목용 + 본문용 + 필요시 데이터용).
  한국어 화면이면 한글 글꼴이 먼저다 (`korean.md`).
- **배치**: 한 문장 설명 + ASCII 와이어프레임
- **시그니처**: 이 페이지를 기억하게 할 단 하나의 요소. 대담함은 **한 곳에만** 쓰고 나머지는 조용히.

후보끼리는 썸네일 크기에서도 확연히 달라야 한다. 프롬프트로만 구분되는 변형은 선택지가 아니다.
대화에 쓸 공통 어휘가 필요하면 `styles.md` (선택).

## 3. 기본값 점검 (후보를 사용자에게 보이기 전)

요즘 AI 생성 디자인은 아래로 몰린다. 주제와 상관없이 나타나면 **선택이 아니라 기본값**이다:
1. 따뜻한 크림 바탕(#F4F1EA 근처) + 대비 강한 세리프 제목 + 테라코타 강조
2. 거의 검정 바탕 + 형광 초록이나 주홍 강조 하나
3. 가는 괘선·모서리 0·빽빽한 단의 신문 레이아웃
4. 똑같은 둥근 카드에 같은 옅은 그림자, 모서리 하나로 통일, 장식용 그라데이션
5. 제목마다 대문자 라벨, `A · B · C` 메타, 버튼 끝 `→`, 작은 라벨에 고정폭 글꼴 (도구·읽기형 목록은 `craft.md` §3)

사용자가 이 중 하나를 원하면 그대로 따른다. 축이 비어 있을 때 이것으로 채우지 않는다.
각 후보의 각 부분에 "비슷한 다른 요청에서도 똑같이 나올 답인가?"를 묻고, 그렇다면 고치고 무엇을 왜 바꿨는지 적는다.

## 4. 덜어내기

나가기 전에 거울을 보고 액세서리 하나를 빼라 (샤넬). 브리프에 봉사하지 않는 장식은 자른다.
페이지 로드 연출·스크롤 등장 효과는 소개·작품형에서만, 그것도 흩뿌리지 말고 잘 짠 한 순간으로. 과한 애니메이션은 AI 생성 티를 낸다.
