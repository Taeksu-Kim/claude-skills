# 빈 상태 · 첫 사용

**읽는 때**: 빈 상태를 설계하거나, "처음 쓰는 사람이 막힌다 / 화면이 휑하다"는 문제.

목표는 제품을 가르치는 게 아니라 **가치를 처음 느끼는 순간까지 가장 빨리** 데려가는 것.

## 빈 상태의 종류 — 구분해서 다르게

| 종류 | 필요한 것 |
|---|---|
| **처음 사용** | 아래 다섯 요소 모두. 가치를 강조하고 예시·견본을 제공 |
| **사용자가 비움** | 가볍게, 다시 만들기 쉽게 |
| **검색·필터 결과 없음** | 다른 검색어 제안, 필터 해제 버튼 |
| **권한 없음** | 왜 못 보는지, 어떻게 얻는지 |
| **불러오기 실패** | 무슨 일인지, 다시 시도 |

**처음 사용 빈 상태의 다섯 요소**
1. 여기에 무엇이 나타날지 ("가져온 거래가 여기에 표시됩니다")
2. 왜 유용한지 (한 줄)
3. 시작하는 방법 — 분명한 행동 버튼 (+ 견본으로 시작하기)
4. 시각 요소 (아이콘·그림, 빈 텍스트만 X)
5. 필요하면 도움말 링크

## 첫 사용 원칙

- **말하지 말고 보여준다**: 별도 튜토리얼 모드가 아니라 실제 기능 안에서, 한 번에 하나씩.
- **선택 가능하게**: 숙련자는 건너뛸 수 있게, 제품 접근을 막지 않는다. "건너뛰기"를 숨기지 않는다.
- **필요할 때 가르친다**: 처음부터 다 설명하지 말고, 그 기능을 만났을 때. 빈 상태가 곧 안내 기회.
- **사용자를 존중**: 뻔한 설명 금지, 짧고 분명하게.
- 꼭 필요한 정보만 먼저 받고 나머지는 나중에. 물어보는 이유가 뻔하지 않으면 설명.
- 둘러보기 투어는 3~7단계, 실제 버튼을 누르게, 다시 볼 수 있게. 본 것·닫은 것은 기억해서 다시 띄우지 않는다
  (저장 키에 사용자·버전을 붙인다).

## 확인
처음 사용자가 첫 가치(예: 첫 가져오기 성공)까지 몇 단계·몇 초인가. 빈 DB 로 실제 띄워서 본다 (`../stages/6-verify.md`).
