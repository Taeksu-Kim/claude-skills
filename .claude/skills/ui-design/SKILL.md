# ui-design — 화면 작업 라우터

**읽는 규칙**: 이 파일 → 아래 표가 가리키는 단계 파일 하나 → 그 파일이 "조건이 맞으면 읽어라"라고 한 것만.
미리 다 읽지 않는다. 상대 경로는 이 SKILL.md 가 있는 폴더 기준 (다른 프로젝트 파일은 절대 경로로 적는다).

## 1. 작업 종류 → 시작 파일

| 작업 | 시작 | 이어서 |
|---|---|---|
| **새 화면·새 기능·새 페이지** | `stages/1-shape.md` (설계 + 화면 종류 결정) | → `stages/2-build.md` → `stages/6-verify.md` |
| **재디자인·전면 개편** ("디자인 바꿔줘", "전면 개편", "전문가 느낌 나게", "투박하다·AI 티") | `stages/3-critique.md` (문제 찾기 — 보고는 짧게, 멈추지 않음) → `stages/1-shape.md` (레퍼런스 + 실제 내용 시안 2개) | 사용자가 시안 고름 → `stages/2-build.md` → `stages/6-verify.md` (수준 비교 포함) |
| **기존 화면 평가 — 고칠 곳이 안 정해짐** ("UX 봐줘", "불편해") | `stages/3-critique.md` (문제 찾기, 코드 수정 X) | 사용자가 고를 범위 → `stages/4-refine.md` 또는 `stages/2-build.md` → `stages/6-verify.md` |
| **정해진 부분 다듬기** ("이 표·필터 정리해줘" / 단순하게 / 마무리 / 예외·에러에 강하게 / 빈 화면·첫 사용) | `stages/4-refine.md` (비평 보고 없이 바로 고침) | → `stages/6-verify.md` |
| **완성 후 점검·공개 전** | `stages/5-check.md` (코드) | → `stages/6-verify.md` (실제 화면) |
| **작은 수정** (문구 하나, 간격, 버튼 하나) | §2 중 "기존 것을 따른다"·한국어 규칙만 지키고 수정. 가치 문장 확인·상태 추가는 하지 않는다 | → `stages/6-verify.md` 의 "빠른 확인" |
| **차트·지표가 들어감** | 위 흐름 그대로 + `dataviz` 스킬 (색·형태·축) | 한국 등락 색은 `topics/korean.md` |
| **Artifact 로 게시하는 페이지** (Artifact 도구) | 형식·테마·확인은 `artifact-design` 스킬이 정한다. 이 스킬에서는 핵심 가치 한 문장(묻지 않고 `가정:`으로 적음)과 `topics/value-density.md` A만 | 로컬 서버가 없으므로 `stages/6-verify.md` 대신 artifact-design 의 확인 |
| **문서** (보고서·docx·pdf·슬라이드) | 범위 밖 → 프로젝트의 문서 디자인 지침 (있으면) | |

애매하면 "새 화면"으로 분류한다 (설계를 건너뛰는 비용이 더 크다). 단 고칠 대상이 요청에 이미 정해져 있으면
비평이 아니라 다듬기다 — 사용자는 고치기를 원한다 (D2).

## 2. 새 화면·개선·다듬기에서 지킬 것 (방향과 무관 — 작은 수정·Artifact 는 §1 표에 적힌 것만)

- **기존 것을 먼저 읽고 따른다** — 그 프로젝트의 CSS 변수·다크모드·컴포넌트 모양·용어. 새 시스템을 만들지 않는다.
  방향(색·글꼴·분위기)은 이 스킬이 정하지 않는다: 기존 화면이 있으면 그것, 없으면 `stages/1-shape.md` 에서 사용자와 정한다.
  단 기존 패턴이 핵심 가치를 가리면 따르되 **부채로 표시**하고 보고에 고칠 방향을 제안한다 — 조용히 복제하지 않는다 (D11).
  **재디자인이면 시각 체계는 따르지 않는다** — 내용·기능·용어·동작과 사용자가 정한 결정(테마·주 색)만 지키고, 글꼴·아이콘·면·위계는
  `topics/craft.md` 레퍼런스에 대 보고 새로 정한다. 기존 것을 따르면 개편이 옛 화면의 수준을 물려받는다 (F1: 아이콘 0→0, 상자 35→23).
- **이 화면의 핵심 가치를 한 문장으로 정하고 시작한다** — 무엇을 얻게 하는 화면인가. **새 화면이면** 사용자에게 확인받는다
  (`stages/1-shape.md` C). 평가·다듬기·점검은 묻고 멈추지 않는다 — `(추정)`으로 적고 진행해 보고에서 확인받는다 (D2·D9).
  끝나면 화면이 그걸 먼저 보여주는지 `topics/value-density.md` 로 점검한다.
- **모든 상태를 만든다** — 기본·hover·focus·disabled·로딩·빈 상태·에러·성공.
- **실제 데이터 범위로 만든다** — 0건 / 1건 / 많은 건 / 아주 긴 이름. 자리표시 데이터로 판단하지 않는다.
- **완료 조건은 실제 화면** — 띄워서 스크린샷을 직접 보고 콘솔 오류 0건 (`stages/6-verify.md`). 코드만 읽은 것은 검증이 아니다.
- 한국어 화면이면 `topics/korean.md` 의 IME·줄바꿈·숫자 규칙은 항상 적용한다.

## 출처

걸리면 `NOTES.md`에 [F] 한 줄 (형식: ../skill-craft/guides/history.md).
