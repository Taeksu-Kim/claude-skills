# 2. 구현 (build)

**읽는 때**: 브리프 확인 후, 또는 비평 결과로 구조를 바꿀 때. **다 하면**: `6-verify.md`.
**전제**: 화면 종류 파일(`../modes/*.md`) 하나를 이미 읽었다. 안 읽었으면 `1-shape.md` B로 종류를 정하고 그것만 읽는다.

## 먼저: 기존 시스템 파악

- CSS 변수(`:root`), 다크모드 블록, 버튼·입력·표·카드 모양, 간격 값, 화면 문구의 용어를 읽는다.
- 새로 필요한 값이 생기면 기존 변수 체계에 추가한다. 화면 안에 임의의 hex·px를 흩뿌리지 않는다.
- **재디자인이면** 시각 체계(글꼴·아이콘·면·글자 위계·회색 단계)는 고른 시안대로 새로 정하고, 변수 이름·용어·동작·사용자가 정한 테마 결정은 유지한다.
- 차이를 발견하면 분류: **토큰 없음**(변수 추가) / **일회성 구현**(기존 컴포넌트로 교체) / **구조 불일치**(흐름·위계가 이웃 화면과 다름) / **단순 결함**.

## 시스템 하나

- 버튼 모양 한 쌍(주·보조), 카드 스타일 하나, 모서리 값 한 체계, 링크 모양 하나, 아이콘 한 계열(굵기 통일).
- 박스 중첩은 2단까지. 카드 안의 카드는 쓰지 않는다 — 묶음은 간격과 정렬로.
- 같은 동작 = 같은 모양·같은 이름. 저장 버튼이 두 곳에서 다르면 하나가 틀렸다.
- 글자 역할(제목·소제목·본문·라벨·숫자·캡션)을 **이름 붙여 한 번만 정의**하고 재사용한다.

## 모든 상태

상호작용 요소마다 기본·hover·focus·active·disabled·loading·error(·success). 화면마다 로딩·빈 상태·에러.
빈 상태 종류가 여럿이면(첫 사용 / 검색 결과 없음 / 권한 없음 / 실패) `../topics/empty-onboard.md`.
판정·경고 문구와 색은 브리프의 경계표(`1-shape.md` C-5)대로 — 만들다가 새 경고·자동 표시를 덧붙이거나 표에 없는 경우가
나오면 표에 먼저 넣고 반례 데이터로 본다.
거르기·정렬·더 보기처럼 화면 일부를 다시 그리는 조작은 **누른 뒤 포커스와 스크롤이 어디로 가나**를 정한다
(결과 제목 `tabindex=-1`로 옮김 / 같은 자리 유지). 앱 전체를 다시 그려 포커스를 `body`로 떨어뜨리지 않는다 (D12).

## 구현 바닥선 (만든 결과에서 확인)

- 대비: 본문 4.5:1, 큰 글자 3:1, 컨트롤·아이콘·포커스 3:1. 색 배경 위 보조 글자는 회색이 아니라 그 색조에서.
- 실제 문구·실제 데이터를 모든 폭에 넣어보고 넘치는 것을 고친다.
- 포커스 링·텍스트 선택 색·표 숫자 모양 같은 브라우저 기본 요소도 팔레트에 맞춘다.
- 브리프의 모든 요구가 화면에 있고 몇 초 안에 찾을 수 있다.
- CSS 선택자 우선순위 충돌 주의 (`.section` 과 `.cta` 가 서로 여백을 덮어쓰는 식).

## 작업 방식

- 한 번에 전체를 다시 만들지 않고 영역 단위로 (diff 를 검토 가능하게).
- 스크린샷은 몇 군데 고친 뒤 모아서 본다. 고칠 때마다 찍지 않는다.
