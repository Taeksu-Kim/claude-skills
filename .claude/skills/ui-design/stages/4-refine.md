# 4. 다듬기 (refine)

**읽는 때**: 비평 후 고칠 범위가 정해졌을 때, 또는 "이 표·필터 정리해줘"처럼 대상이 정해진 요청, "단순하게 / 마무리 / 튼튼하게 / 빈 화면" 요청.
**다 하면**: `6-verify.md`. 다듬기는 **재디자인이 아니다** — 기존 방향·내용·동작·범위 밖은 보존한다.
개념 자체가 틀렸으면 몰래 갈아엎지 말고 그렇다고 말하고 `1-shape.md` 를 제안한다.

## A. 단순화 (distill)

단순함은 기능을 빼는 게 아니라 **사용자와 목표 사이의 장애물**을 빼는 것.
1. 핵심 목표 **하나**를 정한다. 불분명하면 추측하지 말고 묻는다.
2. 정보 구조: 주 동작 1개, 보조 몇 개, 나머지는 숨기거나 메뉴로. 다른 곳에서 말한 것은 반복하지 않는다.
   필요할 때만 드러내기(접기·단계 진행). 비슷한 버튼·폼은 합친다.
3. 시각: 장식색 1~2개 + 중립색 (의미색은 유지하되 색 외 단서 병행), 글꼴 한 벌·크기 3~4개·굵기 2~3개.
   위계에 도움 안 되는 테두리·그림자·배경 제거. 카드 대신 간격과 정렬.
4. 상호작용: 선택지를 줄이고, 흔한 선택은 기본값으로, 모달 대신 인라인, 단계 하나 줄이기.
5. 문구: 군더더기 삭제, 능동형, 전문용어 제거, 제목을 반복하는 소개문 삭제.
6. 하지 말 것: 필요한 기능·결정에 필요한 정보 제거, 접근성 희생, 너무 단순해서 모호해짐, 위계 전부 제거,
   복잡한 영역을 과하게 단순화 (복잡도는 실제 과업 복잡도에 맞춘다).
7. 뺀 것은 무엇을 왜 뺐는지 요약에 적는다.

## B. 마무리 (polish)

1. **증거 모으기**: 대표 크기(모바일·데스크톱)에서 직접 써 본다. 실제 상태·문구 길이·입력 방법을 확인.
2. **우선순위대로 고친다**:
   1. 막힌 과업, 데이터 유실, 오해를 부르는 상태, 접근 불가 경로
   2. 빠진 로딩·빈·에러·성공·비활성·권한 상태
   3. 흐름·위계·반응형·시스템 이탈
   4. 시각·모션 불일치
   5. 코드·자산 정리 (디버그 출력, 죽은 CSS, 중복)
   한 구석만 완벽하게 하고 나머지를 같은 수준 아래로 두지 않는다.
3. **경로 전체 다듬기**: 이웃 화면과 같은 용어·저장 방식·노출 방식 / 주 과업과 현재 상태가 분명 /
   도착·전환·빈·복구 경로가 끊기지 않게 연결 / 그리드·간격 체계에 정렬 (수치뿐 아니라 눈으로 보이는 정렬도) /
   같은 역할 글자는 같게 / 상태별 대비 / 모든 폭에서 확인 (현재 스크린샷만 고치지 않는다).
4. **끝내기**: diff 를 보고 우연한 변경·고아 코드·임시 파일 제거. 끝 조건은 기능 완성 + 경로 전체가 같은 수준.
   `6-verify.md` 의 다시 보기 상한(2회)에 닿으면 남은 차이를 보고하고 끝낸다 (D4).
