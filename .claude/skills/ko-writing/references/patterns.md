# 한국어 AI 패턴 — 고칠 때 2단계에서 읽는다

[강] 한 번만 보여도 고친다. [보통] 같은 글에 몰려 나올 때(대략 3회 이상)만 고친다 — 사람도 쓰는 표현이다.
'지운다'는 무대 장치(대구·펀치·장식)를 걷는다는 뜻이다. 그 문장의 주장은 평서문으로 남긴다.
출처: humanize-ko(im-not-ai·humanizer·stop-slop 기반)에서 골라 고침 — `../THIRD_PARTY.md`. 바꾼 곳은 끝의 "원문과 다른 점".

## 번역투
- [강] "~에 있어(서)" → "~에서", "~을 볼 때"
- [강] "가지고 있다", "~을 갖다" 직역 → 형용사·동사로 ("경쟁력을 가지고 있다" → "경쟁력이 강하다")
- [강] 이중 피동 "~되어지다", "~지게 되다" → "판단된다", "판단한다"
- [보통] "~에 대해(서)" 몰림 → 조사로 ("규제에 대해 논의" → "규제를 논의")
- [보통] "~를 통해", "~와 관련하여", "~에 기반하여" 남발 → "~로", "~해서", "~에"
- [보통] "~에 의해" 피동 → 하는 쪽을 주어로 ("AI에 의해 생성된" → "AI가 만든")
- [보통] 추상 주어 + 만능 동사 ("이 결과는 ~을 보여준다/제공한다") → 사람·기관을 주어로
- [보통] 명사 앞 수식이 세 덩어리 넘게 쌓임 → 문장을 나누거나 뒤로 뺀다
- [보통] 이중 조사 "~에서의", "~으로의", "~으로부터의" → 풀어서. 단순 "~의"는 둔다
- [보통] "~고 있다"가 한 문단 3회 이상 → 일부를 단순 시제로
- [보통] "~할 수 있다" 4회 이상 → 단정으로 바꾸지 말고 일부만 다른 표현으로
- [보통] 한글(영어) 병기 반복 → 처음 한 번만. 광고성 영어(seamless, robust, leverage) → 한국어로

## AI 관용구·부풀리기
- [강] "시사하는 바가 크다", "주목할 만하다", "~시대가 도래했다", "혁신적인" → 지우거나 구체적인 결론으로
- [강] "크게 세 가지로 나눌 수 있다", "다음과 같다" 열거 도입 → 도입구 없이 바로 본론
- [강] "결론적으로", "요약하면", "이를 통해"가 3회 넘음 → 1~2개만
- [강] 광고 문구 "놀라운", "압도적인", "획기적인", "꼭 가봐야 할" → 그게 무엇인지만
- [보통] 의미 부풀리기 "중요한 전환점", "새로운 시대의 신호", 끝의 "앞으로가 더 기대됩니다" → 사실만, 마지막 구체적 사실에서 끝낸다
- [보통] "중요한 것은 ~이다", "핵심은 ~다", "본질은 ~다", "X는 Y의 언어다" → 구체적인 주장으로
- [보통] "~하는 이유다", "결국 ~로 이어진다" 결산, "~할 때입니다" 결말 → "그래서 ~다", 구체 동사로
- [보통] "과제도 남아 있다", "한계도 분명하다" 문패 문장 → 실제 과제를 바로
- [보통] 사전 은유 "청사진", "적신호", "신호탄", "뿌리내리다", 의인화 "기술이 묻는다" → 사실 문장으로
- [보통] "~적", "~성", "~화" 쌓임, "확대·강화·개선·확보·마련·구축" 몰림 → 실제로 하는 행동 동사로
- [보통] "매우", "정말", "대단히" 겹치는 수식 → 하나만, 맺음에는 쓰지 않는다
- [보통] "주목할 점은 ~라는 점이다", "~다는 것이다" → "~다"로 바로
- [보통] 출처 없는 "~라는 분석이다", "전문가들은 ~라고 말한다", "많은 연구에 따르면" → 지우지도 단정하지도 않고,
  과장만 고친 뒤 결과에 '출처 확인 필요'로 알린다

## 구조 — 말하는 대신 무대를 꾸밈 [강]
- A가 아니라 B: 아무도 주장하지 않은 A를 부정해 B를 키움 ("단순한 도구가 아니라 동료입니다") → B를 바로 말한다.
  독자가 실제로 A라고 믿을 때, 실제 대비일 때("판정은 AI의 답이 아니라 실제 화면으로")는 둔다
- 한 줄 펀치: 문단 끝에 앞 내용을 되풀이하는 짧은 문장("이게 핵심입니다."), 단문 나열("변명 없이. 핑계 없이.") → 새 사실이 없으면 지운다
- 뜸 들이는 도입("자, 그럼 살펴볼까요?"), 없는 상대와 다툼("오해하지 마세요", "~라고 생각하실 수도 있지만") → 바로 주장
- 무조건 3개: 의미가 셋이 아닌데 셋으로 맞춤 → 둘로 줄이거나 가장 센 하나를. 진짜 셋이면 둔다

## 리듬·접속
- [보통] 같은 문두(주어·접속사) 연속, 문두 "또한·따라서·즉·나아가" 연달아 → 대부분 지우거나 잇는다
- [보통] 문단마다 "~해야 한다"로 끝남 → 서법은 두고 위치만 앞이나 중간으로
- [보통] "~로 보인다", "~로 판단된다" 반복 → 단정으로 바꾸지 말고 어미만 바꾼다. 겹친 완곡("어느 정도 ~할 수도 있을 것으로 보입니다")은 하나만 [강]
- [강] 연결어미 뒤 쉼표("발전하지만, 대응은") → 쉼표를 뺀다
- [보통] 대시(—, –)로 두 문장 관계를 고르지 않고 이음 → 쉼표·괄호·마침표로. 샘플에 대시가 있으면 둔다

## 서식 — 받는 곳을 먼저 본다
- 장식용 볼드(문장마다 핵심어, 목록마다 "**라벨:** 설명") → 지우고 라벨은 문장으로. 꼭 필요하면 문서 전체에 1~2개
- 짧은 글의 소제목 여러 개, 헤딩·목록 머리의 이모지·화살표, 섹션마다 구분선 → 메일·메신저면 문단으로. 멋 부린 헤딩 → 내용을 말하는 헤딩
- 이어지는 생각을 불릿 3~5개로 쪼갬, 두세 개 비교를 표로 → 문장으로. 일정·사양처럼 나란한 정보는 짧은 목록으로 둬도 된다
- 헤딩을 첫 문장에서 반복("## 성능" 아래 "성능이 중요합니다.") → 그 문장을 지운다

## 채팅·초안에서 남은 것 — 바로 지운다
- 챗봇 잔재("좋은 질문입니다!", "도움이 되셨길 바랍니다", "다음은 ~입니다.") → 감싼 말만 지우고 내용은 남긴다.
  편지 인사·맺음말·서명은 챗봇 잔재가 아니다
- 지식 한계 고백("구체적인 자료는 제한적이지만 ~로 보입니다") → 자료에 없다고만
- 글이 글을 설명함("아래 표는 ~를 비교한 것입니다", "이 문서는 ~순서로 구성") → 독자가 볼 수 있는 건 말하지 않는다

## 고치지 않는 것
인용·제목·고유명사, 그 표현 자체를 다루는 문장. SNS 글 끝의 질문 하나와 해시태그.

## 원문과 다른 점 (왜 고쳤나 — NOTES "만든 과정")
- 대시: 원문은 "예외 없이, 샘플에 있어도" 고침 → [보통], 샘플이 이김 (방향 확인: 사용자 샘플 우선)
- 출처 없는 "~라는 분석이다": 원문은 "직접 서술로" → 말이 세지므로 '출처 확인 필요' 표시로 (지키는 것 2와 충돌)
- 3단계 50점 채점 → 뺌 (숫자 점수 안 씀, 셀 수 있는 건 `scripts/check.py`)
